Getting Started

Install the GreatLibrary CLI globally to start publishing blueprints from any project on your machine.

Install via npm

npm install -g greatlibrary-core
Copied!

Verify installation

greatlibrary --version
Copied!

Requires Node.js 18+ and npm or yarn. The CLI works on macOS, Linux, and Windows.

Authentication

The CLI authenticates through GitHub OAuth. Running the login command opens your browser and authorizes the CLI to publish blueprints on your behalf.

Sign in with GitHub

greatlibrary login
Copied!
1

Browser opens automatically

You will be redirected to GitHub to authorize the GreatLibrary app.

2

Grant repository access

The CLI needs read access to detect your project's GitHub remote URL.

3

Token saved locally

Your auth token is stored in ~/.greatlibrary/credentials.json. You only need to log in once.

Check auth status

greatlibrary whoami
Copied!

Publishing a Blueprint

Run greatlibrary publish from your project root. The CLI reads your configuration files, detects the GitHub remote, and publishes the blueprint to the marketplace.

Publish from project root

cd your-project greatlibrary publish
Copied!

Requirements

CLAUDE.md

Agent instructions file at your project root. This is the brain of your blueprint.

.claude/settings.json

Permissions and tool configuration. Controls what the agent can and cannot do.

GitHub remote

Your project must have a GitHub remote. The CLI links your blueprint to the source repo.

Authenticated

You must be logged in via greatlibrary login before publishing.

What the CLI does

Reads CLAUDE.md and .claude/settings.json from your project root

Detects the GitHub remote URL from your .git/config

Extracts permissions, tool configs, and generates a blueprint manifest

Uploads to the GreatLibrary marketplace and returns a public URL

Blueprint Structure

A great blueprint is more than just config files. Here is what separates a good blueprint from a great one.

1

Clear CLAUDE.md instructions

Write specific, actionable instructions. Define what the agent should do, what it should avoid, and how it should handle edge cases. Vague instructions produce vague agents.

2

Minimal permissions in settings.json

Only request the permissions your agent actually needs. Blueprints with narrow, well-scoped permissions rank higher and build more trust with users.

3

Well-structured repository

Keep your repo clean and navigable. A clear folder structure helps the agent understand the codebase and helps users trust your blueprint before deploying it.

4

Descriptive metadata

Add a clear description and category tags in your CLAUDE.md frontmatter. This helps users discover your blueprint in search and understand what it does at a glance.

Minimum project structure

your-project/ ├── CLAUDE.md # Agent instructions ├── .claude/ │ └── settings.json # Permissions & tools config ├── src/ # Your source code └── package.json # Or any project manifest

Code Examples

Below are sample files for a code review agent blueprint. Use these as a starting point for your own.

CLAUDE.md

Example
# Code Review Agent ## Role You are a senior code reviewer. You analyze pull requests for bugs, security issues, performance problems, and style violations. ## Rules 1. Review every changed file in the PR diff. 2. Flag any SQL injection, XSS, or auth bypass vulnerabilities. 3. Suggest performance improvements when you see O(n^2) or worse. 4. Enforce the project's existing code style — do not impose new rules. 5. Never approve a PR that has failing tests. ## Output Format Return a structured review with: - summary: one-paragraph overview - issues: array of { file, line, severity, message } - verdict: APPROVE | REQUEST_CHANGES | COMMENT ## Constraints - Do not modify any files. Read-only analysis. - Do not run tests — only read test results. - Keep reviews under 2000 tokens.

.claude/settings.json

Example
{ "permissions": { "allow": [ "Read", "Glob", "Grep", "Bash(git diff *)", "Bash(git log *)", "Bash(git show *)" ], "deny": [ "Edit", "Write", "Bash(rm *)", "Bash(git push *)", "Bash(git commit *)" ] }, "env": { "AGENT_MODE": "review", "MAX_FILES": "50" } }

Common permissions reference

Permission Description Scope
Read Read file contents Read-only
Edit Modify existing files Write
Write Create new files Write
Glob Search file paths by pattern Read-only
Grep Search file contents Read-only
Bash(*) Execute shell commands (use patterns to scope) Varies
